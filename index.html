阶段一 能查资料的智能体

建智能体 + 挂知识库。做完能打字问病、它查资料回答。

1创建智能体

工作台左上角 + 创建 → 创建智能体 → 填名称和简介 → 确认。
名称：
复制植保小帮手-你的姓名
简介：
复制帮助农户识别作物病害并提供防治建议。

2建知识库并上传资料

智能体编排页 → 知识 → 文本 → + 新建知识库 → 填名称描述 → 进入知识库 → 上传文件。
知识库名称：
复制作物病害知识库
描述：
复制包含苹果、玉米、马铃薯、水稻、番茄、小麦共6种作物的24类病害诊断与防治知识。
上传内容：把素材文件夹里 kb_docs 下的所有 .md 文件（24 个 + 1 个索引）全选拖进去，等 1~2 分钟解析完。最后确认知识库已绑定到这个智能体。

3写人设 Prompt

左侧 人设与回复逻辑 → 把下面整段贴进去（覆盖默认内容）。
复制你是植保小帮手，一位耐心又专业的农业病害诊断助手，专门帮助农户识别作物病害和提供防治建议。说话亲切通俗，像一位有经验的老农技员。你有一个作物病害知识库，包含24种常见作物病害的详细资料。当用户描述作物症状时，必须从知识库中查找相关信息再回答，不要凭记忆编造。诊断病害时的回答结构：1.诊断结论；2.症状特征；3.防治措施（农业措施加药剂类别建议，不给具体品牌和剂量）；4.施肥建议；5.安全提示。底线：知识库里没有的信息，明确说抱歉，知识库中暂无相关信息，建议咨询当地农技站。

阶段三 不确定时会追问

打开阶段二的工作流：断一根线，插 4 个节点。原来的报告节点和人设都不动。

1删掉一根连线

点 知识库检索 → 生成诊断报告 中间那根线，按 Delete。

2新节点 A：判断诊断明确性（大模型）

拖入大模型节点，改名 判断诊断明确性；知识库节点连到它。
  • 模型：DeepSeek-V3 / V3.2（选不到就用豆包 2.0，纯文字即可，不要视觉）
  • 输入：全部删空
  • 输出格式：JSON
  • 输出字段：reason(String)、is_clear(Boolean)、diagnosis(String)、top2(Array<string>)
Coze 的 JSON 模式会自动多一个 output 字段存原始文本，代码节点就吃它。
系统提示词：
复制你是诊断确定性判断器。根据用户描述和知识库检索结果判断能否唯一确定病害。只输出JSON。is_clear为 true表示能唯一确定；false表示存在易混淆病害需要追问。已知易混淆对——水稻叶瘟vs褐斑（叶瘟梭形灰白中心，褐斑小而多的圆点）、玉米北方叶枯vs灰斑（北方叶枯长条雪茄形，灰斑矩形块状受叶脉限制）、小麦褐锈vs条锈（褐锈散点状，条锈成条带排列）、番茄早疫vs晚疫（早疫同心轮纹，晚疫水渍状扩展加白霉）。
用户提示词：
复制用户描述：{{开始.input}}；知识库检索结果：{{知识库检索.outputList}}；请判断能否唯一确定病害，只输出JSON。

3新节点 B：解析判断结果（代码）

后面拖入代码节点，改名 解析判断结果，判断节点连到它。
先改语言：右侧点「在 IDE 中编辑」，把语言从 JavaScript 手动切成 Python。
  • 输入参数：名 judge_text，类型 String，值 {{判断诊断明确性.output}}
  • 输出字段：is_clear(Boolean)、diagnosis(String)、top2(Array<string>)、reason(String)
代码（整段覆盖）：
复制import json
import re

async def main(args: Args) -> Output:
    params = args.params
    text = params["judge_text"]

    try:
        result = json.loads(text)
    except:
        match = re.search(r'\{.*\}', text)
        if match:
            try:
                result = json.loads(match.group())
            except:
                return {
                    "reason": "JSON解析失败",
                    "is_clear": False,
                    "diagnosis": "",
                    "top2": []
                }
        else:
            return {
                "reason": "JSON解析失败",
                "is_clear": False,
                "diagnosis": "",
                "top2": []
            }

    return {
        "reason": result.get("reason", ""),
        "is_clear": result.get("is_clear", False),
        "diagnosis": result.get("diagnosis", ""),
        "top2": result.get("top2", []),
    }

4新节点 C：选择器

拖入选择器，代码节点连到它。

  • true 不要加引号，类型选 Boolean

实践练习（老师可能要求）

自己搭一个“农产品品质分级”工作流，至少测 5 组输入。

  • 选一种农产品（苹果 / 柑橘 / 茶叶 / 大米…）
  • 定 3~4 个评价维度（外观、色泽、大小、成熟度…）
  • 整理分级标准（可参考国标/行标），写成文档传成知识库
  • 流程：输入 → 知识库检索 → 文本生成评价报告
  • 跑 5 组不同品质的输入，看结果合不合理
